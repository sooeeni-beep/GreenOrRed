3. فقط یک بخش بازشونده در صورت انتخاب کاربر.
4. ژورنال مستقل.
5. محصولات منتخب مستقل.
6. فوتر، برچسب دموی تست و ورودی مدیریت.

گزینه‌های هدر و Hero به بخش مرتبط هوم می‌روند. مقصدهایی که هنوز ساخته نشده‌اند پیام مشخص «مرحلهٔ بعدی توسعه» دارند. لینک، ویدئو، پرداخت یا ورود موفق ساختگی ارائه نشده است.

## ۳. قرارداد اندازه‌ها و دارایی‌ها

- حداکثر عرض کانتینر: **1440 CSS px**؛ در صفحهٔ 1920 پیکسلی بدون scrollbar حاشیهٔ خارجی هر سمت **240px**.
- padding داخلی دسکتاپ: 40px؛ در اندازه‌های کوچک‌تر 28، 22 و 16px.
- CSS Grid و Flex برای شکست چیدمان؛ **هیچ `zoom` یا کوچک‌سازی کلی صفحه** برای موبایل استفاده نمی‌شود.
- چهار ستون دسکتاپ، شکست مناسب در 800 و 540px؛ موبایل Hero و کارت‌ها عمودی می‌شوند.
- اندازهٔ PNG اصلی اندازهٔ نمایش نیست. alpha padding در ساخت خروجی وب محاسبه می‌شود؛ نسبت تصویر و سایز CSS مستقل‌اند.
- `assets/` تنها محل فایل‌های اصلی بارگذاری‌شده است. فایل‌های اصلی تغییر نمی‌کنند.
- `scripts/source-assets.json` فهرست نام‌های دقیق ورودی و `scripts/assets.mjs` نگاشت نام معنایی، پاک‌کردن حاشیهٔ شفاف و تولید WebP را نگه می‌دارند.
- خروجی‌های `public/assets/` در build تولید می‌شوند و در git تکرار نمی‌شوند. در اجرای اولیه `npm run assets` لازم است.
- خروجی وب فقط کوچک می‌شود؛ تصاویر کم‌کیفیت با بزرگ‌کردن مصنوعی جایگزین فایل باکیفیت معرفی نشده‌اند.
- `public/assets/manifest.json` مشخص می‌کند هر فایل از PNG اصلی یا برش مرجع آمده و crop آن چه بوده است.
- قالب لپ‌تاپ/موبایل Hero از فایل خود شماست. دو تصویر صفحه‌نمایش روی آن قرار گرفته‌اند؛ کل صفحه به یک تصویر تخت تبدیل نشده است.
- دکمهٔ بنر آموزشی از خود بنر جداست و مستقل در HTML کلیک می‌خورد.
- رنگ مرجع **Forest / Terracotta** است. پالت بنفش/آبی فایل قدیمی `ChatGPT-Skils/ChatGPT Skils/tokens.js` مبنای این نسخه نیست. بستهٔ آن مخزن بررسی شد؛ نمونه‌های تصویری مصنوعی آن جایگزین assets نهایی نشده‌اند. اسکیل تازهٔ غیرضروری اضافه نشده است.

### فایل‌های لازم برای تکمیل کیفیت تصویری

فایل‌های زیر در assets مستقل موجود نبودند. فعلاً از **تصویر مرجع خود کاربر** برش خورده‌اند و در اندازهٔ بومی خروجی گرفته شده‌اند؛ روی نمایشگر Retina به وضوح فایل مستقل باکیفیت نیستند.

| فایل موردنیاز | fallback فعلی | اقدام بعدی |
| --- | --- | --- |
| محتوای نمایشگر Hero لپ‌تاپ و موبایل | `hero-laptop-screen`, `hero-phone-screen` | تحویل screenshot مستقل یا UI واقعی؛ shell آپلودشده صفحه‌نمایش خالی دارد |
| پنج thumbnail تریدتیوب | `video-1` تا `video-5` | PNG/WebP مستقل با متن دقیق |
| آواتار سه مدرس | `alex`, `sara`, `david` | تصویر مستقل، با مجوز استفاده |
| آواتار سازندگان و MarketMind | `creator-1..4`, `marketmind` | تصویر/لوگوی مستقل |
| آواتار پنج معامله‌گر | `leader-1..5` | تصویر مستقل |
| thumbnail محصول | `product-thumb` | تصویر اختصاصی هر محصول؛ اکنون همان chart مرجع استفاده شده |
| آیکون‌های شبکهٔ اجتماعی فوتر | `social-x/youtube/discord/telegram` | SVG/PNG مستقل؛ لینک رسمی شبکه‌ها نیز لازم است |
| فونت دقیق طرح | Arial و Inter محلی | نام/فایل فونت مرجع برای نزدیک‌ترشدن حروف |

لوگو و برخی آیکون‌های استخراج‌شده نسبت به نسخهٔ داخل screenshot تغییر ظاهری دارند. اولویت به **فایل نهایی آپلودشدهٔ شما** داده شده؛ برای برابری پیکسلی کامل باید همین منابع با مرجع نهایی یکسان شوند.

## ۴. مدیریت و دوام داده

مسیر `/admin` شامل این قابلیت‌هاست:

- افزودن سرویس یا بلوک سفارشی؛ مدخل جدید ابتدا خاموش و Coming Soon است.
- ویرایش عنوان/توضیح انگلیسی و فارسی.
- جابه‌جایی ترتیب با بالا/پایین.
- فعال/غیرفعال‌کردن سرویس و کنترل جداگانهٔ Show on Homepage.
- حالت‌های `active`, `coming-soon`, `maintenance`, `read-only`, `archived`.
- حالت نمایش کارت بازشونده یا بخش مستقل؛ ژورنال و محصولات مستقل می‌مانند.
- روشن/خاموش‌کردن Affiliate و Custom Requests در بلوک توسعه‌دهندگان.
- حذف مدخل با تأیید رابط، سپس ذخیرهٔ صریح. برای نگهداری داده از خاموش‌کردن استفاده کنید.
- Export/Import تنظیمات JSON؛ import ابتدا پیش‌نویس است و ذخیرهٔ صریح می‌خواهد.
- هشدار تغییر ذخیره‌نشده و پیام خطای قابل بازیابی.
- بررسی revision: تغییر هم‌زمان یک نشست دیگر با خطای 409 متوقف می‌شود، نه بازنویسی خاموش.

**ذخیرهٔ اصلی:** Cloudflare D1 در دمو. `localStorage` فقط زبان دستگاه را نگه می‌دارد. تنظیمات ادمین به localStorage وابسته نیستند. سبد خرید صرفاً دموی موقت همان صفحه است؛ پرداخت/سفارش واقعی نیست.

در توسعهٔ محلی Node SQLite از همان SQL migration استفاده می‌کند و در `.dev-state/home.sqlite` می‌نویسد. این فایل وارد git یا انتشار نمی‌شود. آزمون بستن و بازکردن پایگاه داده برای دوام تنظیمات اجرا شده است.

خاموش‌کردن/پنهان‌کردن سرویس با حذف داده فرق دارد. مدل Home فعلاً فقط تنظیمات نمایشی نگه می‌دارد؛ پایگاه واقعی کاربران، معاملات، ویدئو و سفارش‌ها هنوز ساخته نشده است. در مراحل بعد دادهٔ دامنه باید در جدول‌های مستقل بماند و خاموش‌کردن ماژول نباید cascade-delete ایجاد کند.

### امنیت و محدودهٔ این پنل

- این دمو **owner-private** است. اولین مالک احراز‌شده توسط میزبان در `admin_owner` ثبت می‌شود؛ همهٔ APIهای مدیریت شناسهٔ او را سمت سرور بررسی می‌کنند.
- header هویت تولیدی توسط میزبان داده می‌شود؛ در توسعهٔ محلی فقط adapter توسعه یک هویت محلی ثابت دارد و در Worker وارد نمی‌شود.
- درخواست مدیریت بدون هویت 401 و کاربر دیگر 403 می‌گیرد؛ ورودی JSON و مقصد محلی اعتبارسنجی می‌شوند.
- **پیش از عمومی/اشتراکی‌کردن سایت** باید owner bootstrap با allowlist/RBAC صریح ادمین جایگزین شود. تغییر مخاطب این دمو بدون این مرحله مجاز نیست.
- مخفی‌کردن یک کارت به‌تنهایی امنیت سرویس نیست. در آینده API خود هر سرویس باید دسترسی و feature flag خودش را بررسی کند.
- وضعیت Read Only در این نسخه عمل CTA و سبد در همان ماژول را می‌بندد. اعمال فقط‌خواندنی واقعی روی API سرویس‌ها مربوط به مرحلهٔ ساخت آن‌هاست.

## ۵. ساختار کد و اجرای محلی

فایل‌های صفحه زیر `Home Page/` هستند. فایل‌های ریشه (`package.json`, lockfile, `db/`, `drizzle/`, `.openai/`) زیرساخت اجرای برنامه و migration هستند؛ وجودشان برای build از ریشه لازم است.

| مسیر | مسئولیت |
| --- | --- |
| `src/App.jsx` | هدر، Hero، کارت‌ها، accordion و فوتر |
| `src/sections.jsx` | rendererهای Tools / Developers / Education / Videos / Journal / Products |
| `src/Admin.jsx` | پنل مدیریت |
| `src/components.jsx` | تصویر، دکمه، رتبه‌بندی و dialog قابل دسترس |
| `src/style.css` | مقیاس، رنگ، responsive و RTL |
| `shared/config.mjs` | schema، defaults، وضعیت‌ها و فیلتر عمومی |
| `server/api.mjs` | اعتبارسنجی، دسترسی و ذخیرهٔ optimistic concurrency |
| `server/worker.mjs` | ورودی میزبان؛ مسیرهای HTML و API |
| `scripts/assets.mjs` | آماده‌سازی reproducible دارایی‌ها |
| `scripts/build.mjs` | خروجی client و Worker |
| `tests/home.test.mjs` | رفتار و دوام/امنیت تنظیمات |
| `../db/schema.ts` | schema پایگاه داده |
| `../drizzle/` | migrationهای نسخه‌دار؛ بعد از انتشار immutable |

از **ریشهٔ ریپازیتوری** و با Node 24:

```sh
npm ci
npm run assets
npm run dev
```

آزمون و build:

```sh
npm test
npm run build
```

`dist/client` و `dist/server/index.js` خروجی تولید هستند. بازکردن `index.html` با double-click جایگزین سرور نیست؛ API و importهای برنامه به سرور نیاز دارند.

API:

| مسیر | روش | رفتار |
| --- | --- | --- |
| `/api/home` | GET | تنظیمات عمومیِ فیلترشده |
| `/api/admin/home` | GET | همهٔ تنظیمات، حتی خاموش‌ها، فقط برای مالک |
| `/api/admin/home` | PUT | `{config, revision}`؛ ذخیرهٔ معتبر با کنترل هم‌زمانی |

Migration جدید با `npm run db:generate` ساخته و بازبینی می‌شود. جدول‌ها در runtime تولیدی ساخته/تغییر داده نمی‌شوند. migration منتشرشده را بازنویسی نکنید.

## ۶. معیار تحویل این مرحله

- Home واقعی HTML/React، نه screenshot تمام‌صفحه.
- فایل‌های خود کاربر با مقیاس مستقل CSS و fallbackهای مستند.
- بسته‌بودن اولیه و حداکثر یک پنل باز.
- ژورنال/محصولات مستقل.
- مدیریت تنظیمات ذخیره‌شونده و بدون پاک‌شدن هنگام خاموشی.
- responsive و کنترل عرض محتوا.
- جست‌وجوی محصولات، مرتب‌سازی محصولات، سبد نمایشی، dialog، تغییر زبان و کنترل‌های ادمین قابل تست.
- صفحات و سرویس‌های بعدی با وضعیت صادقانهٔ «هنوز متصل نیست» مشخص‌اند.

این تحویل به معنای آماده‌بودن **هوم و ابزار مدیریت هوم** برای بررسی است؛ به معنای ساخت بک‌اند ژورنال، بازارچه، معامله، دوره، پخش زنده یا پرداخت نیست.

## ۷. نقشهٔ راه مراحل بعد

1. **تأیید این هوم و تکمیل assets کمبوددار:** جایگزینی منابع جدول بالا، ثبت مرجع تصویری نهایی، ترجمهٔ کامل جزئیات و نسخهٔ فارسی تصاویر متنی در صورت نیاز.
2. **هویت و نقش‌ها:** تصمیم قطعی احراز هویت سایت عمومی، RBAC ادمین/سازنده/آموزش‌دهنده/کاربر، عدم استفاده از owner bootstrap در سایت عمومی.
3. **Marketplace:** مدل واقعی محصول، صفحهٔ دسته/جزئیات، مالکیت فایل، قیمت، سفارش و سپس درگاه پرداخت؛ جایگزینی سبد دمو.
4. **Trading Journal:** مدل حساب/معامله، واردکردن داده، تحلیل واقعی، حریم خصوصی و محاسبات قابل آزمون؛ داده‌های رتبه‌بندی دمو حذف شوند.
5. **Education:** دوره، مدرس، جلسات، ثبت‌نام و دسترسی به محتوای خریداری‌شده.
6. **Developers:** Affiliate، درخواست سفارشی، پیشنهاد قیمت، وضعیت سفارش و ارتباط مجاز طرفین.
7. **TradeTube و سرویس‌های جدید:** محتوا/پخش واقعی، moderation، حقوق محتوا؛ افزودن renderer با همان رجیستری بدون بازنویسی Home.
8. **انتشار عملیاتی:** دامنه و محیط production مستقل از تست، backup/restore پایگاه، پایش خطا، migration آزموده‌شده، عملکرد، دسترس‌پذیری، سیاست‌های رسمی و اتصال لینک‌های نهایی.

### قاعدهٔ تغییرات آینده

شناسهٔ ماژول پایدار بماند. برای افزودن سرویس تخصصی، renderer و قرارداد داده اضافه شود؛ Home نباید دوباره از صفر نوشته شود. خاموشی = حفظ داده. حذف دادهٔ واقعی فقط با فرآیند صریح دامنه و امکان بازیابی. تصمیم جدید مهم، تاریخ و علتش به همین README افزوده شود.
